You are an expert software architect specializing in requirements-to-design traceability.

## **Task**
Given:
1. **A list of requirements** in JSON format
2. **A class diagram** in JSON format
Your task is to generate a **traceability JSON** that links each requirement item to one or more classes, methods, or attributes from the class diagram, following strict architectural reasoning rules.

## **Input**
Requirements:
{requirement}

Class diagram:
{class_diagram_json}

## **Traceability Rules**
Use the following reasoning rules when building links:
### **Rule A — Actor ↔ Class Matching**
If a requirement mentions an **actor**, map it to any class whose name matches or represents that actor.
### **Rule B — Action Verb ↔ Method Matching**
If a requirement includes an **action verb** (e.g., delete, confirm, view), map it to class methods that semantically correspond to that action.
### **Rule C — Responsibility Delegation**
If the matched method belongs to a high-level class, also link to lower-level classes logically responsible for executing the operation (e.g., Manager → Repository → Server).
### **Rule D — UI and System Reactions**

If the requirement describes:
* notifications
* confirmations
* cancellations
* blocking/unblocking UI
Map them to UI-related classes/methods or explicit state attributes when the class graph contains such attributes.

## **Output Format**

Return exactly one complete JSON object with a top-level `traceability` array:
```json
{
  "traceability": [
  {
  "requirement": "<requirement id>",
  "content": "<original text>",
  "links": [
    {
      "target": "<class, class.method, or class.attribute>",
      "reason": "<why they match>"
    }
  ]
  }
  ]
}
```
## **Very Important**

* Output exactly one item for every supplied requirement ID and copy each ID verbatim.
* Never emit a blank, placeholder, duplicate, or invented requirement ID.
* Do NOT invent new classes, methods, or attributes that do not exist in the class diagram JSON.
* If no match can be found, output `"links": []`.
* Explanations must reference Rules A–D.
* Keep each reason to one short sentence and include only directly supporting targets.

Return only the JSON object without markdown fences or explanations.
